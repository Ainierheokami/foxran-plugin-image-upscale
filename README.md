# 图片放大（foxran-plugin-image-upscale）

Foxran Agent 工具插件：输入一张图，输出高清大图。适合 GPT Image 2 生成后排版合适、但单图分辨率低导致细节发糊、文字乱码的图片。

## 原理

1. **甜点尺寸切块**：按放大倍率算出输出尺寸，从 `tile_sizes`（默认 1024x1024 / 1536x1024 / 1024x1536）里挑块数最少的一种，相邻块保留约 15% 冗余。
2. **校对文字**（`proofread`，默认开）：先把整张图交给视觉模型，按阅读顺序读出全部文字，按上下文找出错别字、形近字和乱码（比如“做蠣启德跑道前端”应为“坐落启德跑道前端”），得到一份“图里画的 → 正确的”修正清单。用户写在命令后面的文字作为校对依据。校对失败不影响放大。
3. **逐块重绘**：每块先插值放大到该块的请求尺寸，再交给图像编辑模型（推荐 `gpt-image-2`），要求保持画面范围和构图不变、画清细节，并按修正清单把本块里的错字改对。
4. **对齐（只在需要时）**：GPT Image 2 通常会保持画布位置不变，这时不做任何变换，避免重新采样把图弄软。只有检测到整块平移或伸缩超过 1 像素时，才用 SIFT 特征点 + RANSAC（ECC 细化）把它对回去；位移中位数达到 3 像素时，再用平滑光流修正局部挪动。
5. **只纠正真正的错位**：在比字形更粗的尺度上比较模型图和原图的结构（局部相关性）。颜色更鲜艳、天空更亮、乱码被改成正确的字，都不算偏差；只有成片的内容挪位、消失或凭空出现，才会重绘一次，仍不行就用原图插值填补那一片。整块对不齐时，整块退回插值。
6. **拼缝与校色**：在冗余区里用动态规划找两块差异最小、而且都和原图一致的路径作为拼缝。每块只拟合一个整体的颜色变换（各通道一个增益和偏移）来消除模型的偏色；拼好后再在很粗的尺度上按原图做一次亮度校正。两步都不会把原图的内容画回去，因此不会产生重影。

7. **局部换切法重绘**（`refine`，默认开）：切线正好切开一行字时，相邻两块各画半个字，怎么重画同一块都对不上。所以第一轮拼好后，找出这些误差区域：重绘失败或整块对不齐的块、用原图插值填补过的地方、相邻两块在冗余区里画得不一致的地方。只在这些地方局部换一种切法重切：误差区域放得进一块，就切一块以它为中心、四周带上下文的块，让被切开的内容完整落在一块里；放不下（比如整块失败）就按 `refine_tile_sizes` 和更大的冗余 `refine_overlap_ratio` 另切网格。新切口会在 `refine_margin` 范围内挪到原图里最空的行列上，避免又切到别的字。新块照样对齐、校色、检测偏差，只在误差区域里，以及它自己和原图一致的地方替换第一轮的结果，在空白的切口处做窄羽化衔接。局部重绘最多调用 `refine_max_tiles` 次模型，优先补大的区域。

某块自动重试（`retries`）后仍失败时用普通插值顶上，结果里会注明，可以事后用 `/放大重试` 只重绘这几块；透明通道单独插值后保留。

## 工具

`image_hd_upscale(path, scale=2, text_hint="", job_id="", retry_tiles="")`

- `path`：本地路径、http(s) URL 或 `url-<uuid>` 引用
- `scale`：1~4；只修乱码不放大时传 1
- `text_hint`：图中文字的正确内容（可选）
- `job_id` / `retry_tiles`：重试某次放大的部分切块，见下文“单独重试”

## 命令

插件自带直通命令，装好后会出现在设置页“命令策略”里，默认开启：

```
/放大 [图中文字的正确内容]   （附带图片，或引用一条带图片的消息）
```

也可以用 `/高清`、`/upscale`。命令后面的文字会作为 `text_hint` 传给模型。

```
/放大重试 [任务号] [块号]
```

也可以用 `/重试放大`、`/upscale-retry`，见下文“单独重试”。

块数超过 `max_tiles` 或输出像素超过 `max_output_pixels` 时会自动降低倍率。

## 单独重试

每次放大都会给一个 6 位任务号（写在结果里），并把原图、切块方案和每块结果存到 `data/image_hd_upscale/jobs/<任务号>/`。这个目录不在 tmp 下，宿主清理临时文件时不会删掉；默认一直保留，可用 `keep_jobs` 限制条数。

重试只重绘指定的块，其余块原样保留，再重新拼接：

| 写法 | 重绘哪次放大 | 重绘哪些块 |
| --- | --- | --- |
| `/放大重试` | 本会话最近一次 | 失败的块 |
| `/放大重试 3fa9c1` | 任务 3fa9c1 | 失败的块 |
| `/放大重试 2-3` | 本会话最近一次 | 第 2 行第 3 列 |
| `/放大重试 3fa9c1 2-3,1-1` | 任务 3fa9c1 | 指定的块 |
| `/放大重试 3fa9c1 全部` | 任务 3fa9c1 | 全部块 |

局部换切法重绘的结果也存在任务目录里。重试某几块时，没碰到这几块的局部重绘结果原样复用，只对碰到这几块的误差区域重新局部重绘。

“失败的块”指自动重试后仍然重绘失败、对不齐或偏差超过 `max_deviation` 的块。重画失败过的块时（自动重试的第 2 次起，或用 `/放大重试` 重画之前失败的块），提示词会额外强调“画面范围和每个元素的大小位置必须和输入一致”，专门针对模型只挑画面里某张卡片放大铺满的情况。同一会话里有多次放大时，建议带上任务号；不带任务号时，结果里会注明用的是哪个任务。引用 WebUI 里的放大结果图也能定位到对应任务。也可以写成 `/放大 重试 3fa9c1 2-3`。

## 配置

首次加载时生成 `config/image_hd_upscale.yaml`，各项说明见 [config_template.yaml](config_template.yaml)。

WebUI 的设置页里打开 `image_hd_upscale.yaml` 是插件自带的可视化编辑器（分模型、倍率与切块、重试与修正、局部换切法重绘、输出与记录五组，模型从 models.yaml 里按 image_edit / vision 标签列出），也可以切到源文件直接改。保存时会校验取值范围，并保留文件里的注释（需要宿主 4.5.3 及以上）。最常改的是 `model_name`：填 models.yaml 里 gpt-image-2 的模型名；留空则按 `image_edit` 标签轮询。

## 排查

结果里会说明哪些块用原图插值填补了多少。想看每块的具体情况，把配置里的 `save_tiles` 设为 `true`，每块的模型原图、修正后的结果和填补区域会保存到 `tmp/image_hd_upscale/debug/<时间>/`；局部换切法重绘的块以 `fix<序号>` 开头。

## 前端

设置页源码在 `web/`，构建产物是根目录的 `index.umd.js`（已提交，宿主直接加载）：

```bash
cd web && npm install && npm run build
```

## 依赖

宿主自带的 Pillow、numpy、opencv-python；宿主版本 >= 4.5.3。
